# 게임 브리프 — 장사 시뮬레이터 (Shop Simulator)

> 한 장짜리 기획서 (`modes.rigor: minimal`). 이 문서가 코드 작성 전 유일한 설계 문서다.

## 한 줄 소개

물건을 싸게 사서 비싸게 파는 2D 장사 시뮬레이션. **장사 종류(가게 타입)를 데이터로 정의**해서
편의점·무역 상인·노점 식당을 같은 엔진 위에서 모두 플레이하고 테스트할 수 있다.

## 플랫폼 / 엔진

- Godot 4.7, GDScript, 2D, PC(Windows/Linux) 데스크톱, 1280×720

## 핵심 루프 (하루 단위)

1. **아침 준비**: 시장 시세 확인 → 물건 사입 → 판매가 설정 → 업그레이드 구매 → (무역) 도시 이동
2. **영업**: 손님이 한 명씩 들어온다. 각 손님은 원하는 물건, 예산, 가격 민감도를 가진다.
   - 가격이 적당하면 바로 산다 / 너무 비싸면 그냥 간다 / 애매하면 **흥정**을 건다
   - 흥정: 수락 · 역제안 · 거절 중 선택 (역제안은 손님 인내심 안에서만 성공)
3. **마감**: 매출·원가·폐기·임대료 정산, 평판 변화, 유통기한 경과, 다음 날 시세 변동

## 시스템 (모두 필수)

| 시스템 | 내용 |
|---|---|
| 시세 변동 | 품목별 가격 배수가 평균으로 돌아가는 랜덤워크. 이벤트(폭등/폭락)가 일시적으로 끼어든다. 무역 타입은 도시마다 시세가 따로 움직인다 |
| 손님 AI | 손님 유형(알뜰형·보통·부자 등)마다 예산·가격 민감도·흥정 성향·인내심이 다르다. 방문 수는 기본 유동인구 × 평판 × 업그레이드 |
| 재고 / 유통기한 | 창고 용량 제한. 재고는 입고 묶음(lot) 단위로 원가와 남은 기한을 가진다. 선입선출 판매, 기한 0이 되면 폐기 |
| 제조 (식당) | 레시피가 있는 품목은 판매 시 재료를 소모한다 |
| 가게 확장 | 창고 확장, 간판(유동인구↑), 냉장고(기한 소모↓), 직원(흥정 자동 처리·판매량↑) 등. 효과는 데이터로 정의 |

## 가게 타입 (데이터: `assets/data/shop_types.json`)

| 타입 | 특징 |
|---|---|
| 편의점 | 품목 수 많음, 유통기한 짧은 식품 + 기한 없는 공산품, 안정적인 유동인구 |
| 무역 상인 | 손님 대신 도시 간 시세 차익이 핵심. 이동 비용·이동 일수, 도시별 시세 |
| 노점 식당 | 재료를 사서 요리(레시피) 판매. 재료 기한 매우 짧음, 손님 흥정 적음 |

새 타입은 JSON에 항목만 추가하면 된다 — 코드 수정 없음.

## 테스트 요구사항

- **모든 가게 타입이 자동 테스트 대상**: 테스트 러너가 `shop_types.json`의 모든 타입을 순회하며
  고정 시드로 N일을 자동 플레이하고, 돈/재고/평판이 유효 범위에 있는지 검사한다.
- 각 시스템(시세, 재고, 손님, 흥정, 업그레이드, 제조)은 단위 테스트로 공식과 경계값을 검사한다.
- 실행: `godot --headless --path . -s res://tests/run_tests.gd` (실패 시 종료 코드 1)

## 승리 / 패배

- 목표 금액 달성(타입별 `goal_money`) 시 승리, 돈이 0 미만이고 재고도 없으면 파산
